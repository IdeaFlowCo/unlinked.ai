# Header autocomplete

Every standalone-runtime page with the header search form enhances the existing GET `/network?q=…` form with people, company and navigation suggestions. The People directory (`/network`) hides the header field; its own toolbar search filters live (`docs/network-controls.md`). The layout uses the shared Public Sans typography, indigo tokens and profile avatars. The QR scan control stays beside search.

Focusing the field sends one `/search-suggestions?q=` warm-up (at most every 10 s), which starts loading the index and returns nothing. After two characters and a 120 ms pause, the browser requests `/search-suggestions?q=…`. While the request is pending, earlier rows that still contain every typed word stay visible. Answers already seen on the page are kept in memory only (at most 40, gone with the page) and redraw at once. The public People reader returns at most five people and three distinct companies. Name matches rank ahead of other professional text; exact names and name prefixes get priority. When at least five people have every word in their name, only names are scanned, with the same result as the full ranking. Companies complete against visible position company names, deduplicated without case. Roles, skills and professional text use the directory's existing word matching. No model runs for a keystroke.

This browser-only endpoint accepts only one `q` parameter (up to 200 characters) and uses the published, whitelisted projection for signed-in and anonymous users alike. It does not read a private network, infer an account, or search contact-card data. Responses are `no-store`, and the browser stores no query history. Building the shared index reads the graph (about 0.7 s live), so suggestions reuse the last verified index: unchanged for 10 s, then for up to 60 s while one background read refreshes it (`suggestFreshMs` / `suggestStaleMs` on the reader; every other public read still checks the source each time). A failed refresh drops the kept index, so a revoked or unavailable publication fails closed on the next suggestion, and unavailable data never falls back to private imports. A hidden or removed profile can therefore appear in suggestions for up to 60 s; its profile page reads fresh. Its separate site-wide budget permits 600 requests per minute and eight in flight without using the full-page budget.

The progressively enhanced combobox supports Arrow Up/Down, Enter, Escape, Tab, click-away and Cmd/Ctrl+K. Focus stays in the input while keyboard selection is announced through `aria-activedescendant`; status and errors are announced politely. IME composition suspends lookup. Autocorrect, autocapitalize and spellcheck are off. On phones and touch screens the field is 16px so iOS Safari and WKWebView do not zoom on focus. A tap on a suggestion keeps the panel open through the field's blur so the tap navigates. Requests are canceled on newer input, closing, blur and page exit, with a generation check to reject late responses and a six-second request timeout. The native form and “See all results” (the same URL the native form submits, with its hidden filters) remain available when suggestions fail. Without JavaScript the original search and QR links still work.

Verification: `node --test tests/omni-search.test.mjs tests/topbar-me-menu.test.mjs tests/shared-people-browser.test.mjs tests/profile-card.test.mjs`. Browser smoke checks should also cover mobile width, a slow response overtaken by a later query, offline fallback, company/profile navigation and native Enter submission.

Latency (2026-10-09, M4, synthetic 16,000-profile / 48,000-edge snapshot, 22 name/company/role queries through the HTTP handler): p50 about 10 ms, p95 about 30 ms with the index warm, including when each graph read is simulated at 700 ms. Without index reuse, each suggestion would wait about 740 ms.
