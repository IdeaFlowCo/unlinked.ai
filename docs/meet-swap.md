# Swap numbers and network asks

The standalone Unlinked runtime owns this feature. It is off by default. The independent switches are `UNLINKED_MEET_SWAP=on` and `UNLINKED_MEET_ASKS=on`. The asks switch also requires the swap switch and the existing Unlinked–OpenChat messaging session secret. Enabling the flags neither makes a QR public nor sends a message. Each host creates individual QR links from their card or Scan page after explicitly enabling their shared phone number.

A printed QR opens `/m/<owner-card-capability>?e=<event>`. The path uses the existing random owner card capability so QR sharing does not expose a guessable username-to-phone mapping. Each event value comes from the owner-created record. The owner can disable a specific QR, and making their card private, hiding their number or resetting the card closes all of its swap links. A group invitation adds `g=<group>` and uses the existing active group flyer, with organizer and flyer validation. People opt in on the swap and finish joining through that group’s normal sign-in and approval flow. Contact fields and asks remain private after joining.

The swap requires at least one reachable channel. Numbers are normalized to E.164, with ten-digit local input treated as North American. Instagram, X, and LinkedIn accept profile links or handles. Contact channels are claims. An exact shared channel can extend one existing private contact with compatible details. A submission spanning two contacts, or disagreeing with an existing channel, keeps its own private encounter for review. The encounter is the audit record for the original entry and its matching decision. The invite list uses only explicit gathering opt-ins and can filter by event, name or interests. Contact links open existing user-controlled apps. Text back fills the Messages composer using the host’s device and still requires the host to send.

The visitor can save the host’s vCard as soon as they swap. The host gets an in-app notification and a private record with timestamp, source event, one-liners, channel actions, and a quick note. Swap notifications are excluded from the email preference and send paths. The runtime keeps a bounded per-owner record in Neo4j and includes it in the original owner’s Unlinked export and deletion. Submitted data stays out of public views, web caches, analytics, emails, and agent grants. Anonymous traffic has process-local per-IP and per-QR quotas, and the canonical ingress must continue overwriting the forwarded peer address.

Network asks use OpenChat’s existing owner-private `/api/private/asks` and `/api/private/things` operations through the confidential, short-lived OpenChat session exchange. This is the same store used by `oc_save_ask`, `oc_list_asks`, and `oc_update_ask`. A visitor’s optional ask is durably captured with the swap, then synced as a private ask on a stable OpenChat person record. Only the name and ask are passed to OpenChat. If OpenChat is unavailable, the person card keeps a retry action. Synced asks follow the existing OpenChat/Noos export, retention, and deletion boundary. The original Unlinked record and its encounter audit follow Unlinked’s lifecycle. A linked login must switch back to the original sign-in to use the feature.

The capture bar defaults to the person on person pages. Elsewhere it resolves a name against QR and OpenChat contacts, asks the owner to select someone when names overlap, and waits for explicit confirmation. The OpenChat-backed list shows themes, status, source and date. Suggestions are based on shared keywords in the owner’s private swap one-liners, with no model call or publication. The microphone uses on-device recognition where the browser supports it. System keyboard dictation and typing also work. No audio is sent to Unlinked.

The v0 has no automated text sender, phone verification, Google sign-in, contact address-book sync, or Buzz notification publishing. An existing authorized OpenChat connector can read the saved private asks through its normal tools.
