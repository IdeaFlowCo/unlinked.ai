Jacob's October 13, 2026 request distinguishes implementation from planning. The browser/runtime changes implement **LinkedIn QR support** (`unlinked-d4w`) and advance **paste a LinkedIn URL** (`unlinked-79f`). Profile social links are Fable's separate slice (`unlinked-8dm`). **Chat with someone’s agent / agentbook** (`unlinked-ptc`) stays planned, coming soon, and explicitly unimplemented. **LinkedIn connection queue** (`unlinked-uug`, `.1`, `.2`) is design and tracking only; no LinkedIn invitation executor or sending is enabled.

## Person lookup

The scanner at `/scan` and `/meet` accepts a normal LinkedIn profile QR, including the tracking parameters generated by Share my profile. The browser classifier and server share `src/utils/linkedin-profile-url.mjs`: exact HTTPS LinkedIn host, `/in/<slug>` only, bounded Unicode slug, canonical case and percent encoding, tracking discarded. Foreign URLs, credentials, alternate ports, short links and arbitrary redirects are rejected. Scanning still stops the camera and offers a visible Open/Cancel confirmation. Open leads to the same `/people/lookup?url=…` route as a pasted URL.

Header search offers **Find this person from LinkedIn** for a valid pasted URL; the People search accepts it on Enter. Add a person also links to the dedicated form. Existing published people resolve by canonical URL before a provider request, with confirmed membership preferred over imported copies. Namesakes never match by name. A failed public directory read does not mean the person is missing and does not trigger an expensive fallback.

If the person is absent, a signed-in member chooses **Find person** to retrieve a preview through the existing operator-configured profile adapter. This is independent of signup's self-claim and lifetime three-attempt limit. Both routes share the same durable global provider reservation, pacing and allowance. General lookup adds a separate 20-attempt UTC-day allowance per owner; failures count. The one-day professional cache carries an observed time. The adapter loads once from the existing private host configuration; no SDK update or new provider credential is needed. When unavailable, the page offers manual Add by name with a truthful status.

The preview shows professional name/headline/location, about, experience and education, with cached/live provenance. Raw provider bodies, photos, email, phone and credentials are excluded. The adapter has no viewer identity, graph access, claim or messaging operation. Timeouts hold even when an adapter ignores cancellation. A lease that was replaced or whose owner was removed cannot write a late result. `UnlinkedPersonLookup` contains only owner-scoped quota state; shared public-professional previews remain in the existing `UnlinkedSignupCache`. Recovery includes the new quota label.

**Add to my people** requires the current member's CSRF and a short-lived candidate token. It rechecks the published identity and the owner's existing rows, then stages the existing private one-row added-person import. The saved contact retains name, LinkedIn address, current headline and company; the richer work/education preview is not a new public publication. Identical retries reuse the deterministic import receipt. Background indexing uses the existing worker; the initial redirect does not claim indexing finished. This never creates a signed-up member, claims that person's identity, or sends them a LinkedIn/Unlinked invitation. A later public profile creation policy is a separate slice if desired.

The routes are browser-only. Existing MCP and agent HTTP scopes, grants and endpoints do not expand. Lookup budgets survive sessions/restarts, and account deletion removes its general lookup counter.

## Connection queue design — unimplemented

Keep one private durable queue per Unlinked owner. A row identifies its canonical LinkedIn target and the exact source action, person reference, added time, chosen sender and execution receipt. Adding several people offers a compact review sheet: **You added 6 people. Connect on LinkedIn?** The user can select, deselect or dismiss. Automatically importing an old network must not enqueue every historic connection. Native Unlinked acceptance is independent of LinkedIn relationship status.

Use statuses `queued`, `awaiting_approval`, `approved`, `attempting`, `pending`, `connected`, `failed`, `paused` and `unknown`. Approval binds the selected targets, verified sender account, executor permission, expiry and attempt budget. A queue can wake an agent to **review**; it cannot authorize sending merely because someone opened a browser or installed a skill. Delivery attempts require a lease/idempotency key. Unknown outcomes require readback rather than a blind send retry. Rate limits, account challenges, identity changes and source revocation pause execution. Reconnecting never switches sender silently.

| Option | Fit | Dependency before implementation |
| --- | --- | --- |
| Agent skill check-in | Portable first queue consumer; existing agent can inspect and report pending targets | Owner-scoped queue API and separately consented execute capability; verified browser/API transport |
| Browser next-open / Chrome extension | Useful when the user already has a personal LinkedIn browser session | Explicit active-account verification, stable reviewed UI actions, resume/error receipts and no unexpected page-load sends |
| Link Claw local app | Optional local service that can host a persistent executor | Establish its actual code/auth contracts first; no working Link Claw integration is assumed |
| Unipile | Strong server transport once personal sources exist; supports profile resolution and invitations | Implement the personal-role source model in the existing sync plan; sender cannot be the system/Inigo account |

Recommendation: specify the shared queue and portable agent skill contract first (`unlinked-uug.1`), then decide the executor against real account/transport acceptance (`unlinked-uug.2`). Reuse the October 12 [personal LinkedIn sync plan](https://github.com/IdeaFlowCo/unlinked.ai/blob/docs/personal-linkedin-sync-plan/docs/personal-linkedin-sync-plan.md) and `unlinked-but` (Unlinked Plus), preserving personal/system source isolation. None of those future provider connections, permissions or workers is created by this change.

Primary provider references, checked October 13: [retrieve profiles](https://developer.unipile.com/docs/retrieving-users), [invite users](https://developer.unipile.com/docs/invite-users), [provider limits](https://developer.unipile.com/docs/provider-limits-and-restrictions). The established runtime adapter remains v1; do not silently migrate to the separately documented v2 API or treat example limits as an entitlement guarantee.

## Validation and release

Behavior tests cover URL/QR parsing, exact published resolution, provider-field whitelisting, cache/typed errors/deadline, authentication/CSRF, private staging and replay. The disposable Neo4j CI fixture checks cross-process reservations, pacing, per-owner daily caps, cache expiry and inactive-owner fencing. Existing scanner/search/signup tests remain relevant. Production acceptance must confirm the configured adapter is available, exact source deployment, a read of a permitted absent target, and private add/indexing, without claiming someone else's identity. Source submission alone does not prove deployment or provider readiness.
