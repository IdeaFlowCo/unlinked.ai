# Canonical app host cutover

The existing production-backed app can use exactly `https://www.unlinked.ai` or its rollback host `https://private.unlinked.ai`. The private graph/assets/root, exact issuer/subject owner mapping and internal-only operations remain the same. This source change does not alter DNS, TLS or the provider registry. Public Next.js serves the canonical callback through an external rewrite to the actual current private callback for transactionless route preflight. That400 receipt does not prove a signed canonical callback. Full uploads never use this Vercel rewrite.

Before activation, retain the current source packet, manifest, TLS pair, DNS zone and a verified current-data paired backup. Extend the existing production client to the exact canonical origin and `https://www.unlinked.ai/auth/callback/ideaflow`, preserving the private callback for rollback. Issue/read back a valid certificate for the canonical host and preserve the current private certificate. Prepare a new immutable release packet: copy `nginx.canonical.conf` to that packet's `nginx.conf`; set the manifest origin and callback to the canonical values; use the final merged source pin and final-head readiness receipt. The helper passes only the validated manifest origin into Compose; ambient origin cannot override it. Run `python3 /release/pilot.py canonical-readiness --manifest /private/canonical-release.json --execute` before public DNS cutover; it keeps the normal `start` DNS guard unchanged while proving the canonical candidate directly at `34.10.134.247` with www SNI/Host, TLS validation, anonymous landing, transactionless callback, auth-start redirect and secure login cookie attributes.

The account grant issuer and signing-key derivation are origin-specific. Before this first public cutover, confirm no active private-host grants remain (the operator test grant was explicitly revoked). Users create new canonical setup after signing in; do not silently invalidate future active grants during a later origin migration. Cookies and OIDC transactions are host-scoped, so complete a fresh canonical sign-in rather than carrying private-host cookies or pending callbacks.

Switch only the scoped public app DNS/ingress after canonical host, certificate, client and runtime are ready. Verify anonymous landing, chosen-account callback, returning imports, complete upload counts, AI and MCP on the canonical URL. Preserve the private-root rollback packet and exact previous DNS records; roll back source/ingress/DNS without overwriting graph or assets. The apex may redirect to the canonical www host. Public profiles, discovery ACLs and legacy imports are separate source work; this host operation never broadens stored data visibility.
