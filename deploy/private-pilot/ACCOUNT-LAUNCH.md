# Open account launch

This standalone private runtime supports open signup after the existing OIDC code/PKCE/state/nonce/JWKS verification. The exact issuer and opaque subject resolve the existing active private owner, or atomically create one new owner in the separate operational graph. No invitation or additional email_verified flag is required. Authenticated email is display information in this slice; legacy same-email reconciliation belongs to the separate migration lane and never transfers another owner’s data implicitly.

Upload has one disclosure/action covering private retention and bounded OpenAI processing; there is no separate production consent checkbox. New production uploads record `public-professional-archive-openai-v2`, making safe professional profile and connection DTOs eligible for the shared People projection while keeping original archives and contact details private; older private-v1 receipts remain owner-private. Complete ZIP or Connections-only ZIP/CSV is accepted up to 64 MiB, with 8 MiB per selected CSV, 40 MiB selected expansion, 2,000 entries and 100,000 parser records. Only Connections/Profile/Positions/Education/Skills CSV members are inflated; all other original bytes remain recoverable in the privately retained ZIP with an immutable manifest. The browser request stages the original archive and `uploaded` receipt before redirecting to `/profile`; a singleton server worker resumes via Noos pending-job discovery and CAS leases after navigation, disconnect or restart. Profile/Positions/Education/Skills rows are staged before connections so the own profile can appear before the final publication fence. Publication uses bounded chunks and one final fence; no first-N truncation. One process-wide upload body at a time bounds memory, with a 1 GiB runtime cap and 65 MiB multipart ingress cap.

Returning users rediscover current and pending imports in their owner scope; Settings shows receipts and progress/status for each file. My network and the owner MCP tool search all current published owner imports, bounded to 1,000 imports/100,000 observations; an exceeded bound fails explicitly. Everyone search uses the separate complete published professional index, initially bounded to 20,000 profiles/100,000 directed edges and ranked from at most 200 lexical candidates. Source IDs and archive provenance remain unchanged. Connection observations are not asserted to be second-degree edges. Every search rechecks complete live publication state after model completion.

Settings issues an account search-only bearer for current and future imports plus the published professional People index until revoked. Audience `unlinked-account-tools-v1`, tools `unlinked_search_network` and `unlinked_search_everyone`, no raw assets, no generic graph access, no owner parameter. Older single-tool grants remain valid for owner-network search only. The grant and revocation persist in owner-private operational resources; the domain-separated signing key derives from the approved private graph secret, so unchanged secrets preserve grants across restarts. Replacing that secret revokes every old account grant. Browser sessions remain 15 minutes. Copying MCP setup is configuration, not proof that a client connected; a successful authenticated real MCP call is the connection acceptance receipt.

The source tests explicitly distinguish synthetic identity/filesystem persistence from production callback/Noos/model evidence. They cover native upload, disconnected browser controller plus replacement worker, profile-first staging, crash/replay, lease expiry, two-owner isolation and tombstone races, but they are not live Noos/model/browser proof. Live friends' archives remain gated on the exact deployed OIDC callback, actual browser synthetic Connections-only/full-ZIP upload, background continuation, complete counts, real model, MCP/revocation and recovery acceptance. The existing private host is not upgraded by merging source.
