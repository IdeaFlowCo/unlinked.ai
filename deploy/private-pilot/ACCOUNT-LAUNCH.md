# Open account launch

This standalone private runtime supports open signup after the existing OIDC code/PKCE/state/nonce/JWKS verification. The exact issuer and opaque subject resolve the existing active private owner, or atomically create one new owner in the separate operational graph. No invitation or additional email_verified flag is required. Authenticated email is display information for ownership. The recovered-account lane can use server-held signed Ideaflow email evidence to offer a one-time CSRF-protected "old Unlinked profile" confirmation, but it never transfers another owner’s data implicitly or trusts typed/uploaded email.

Upload has one disclosure/action covering private retention and bounded OpenAI processing; there is no separate production consent checkbox. New production uploads record `public-professional-archive-openai-v2`, making safe professional profile and connection DTOs eligible for the shared People projection while keeping original archives and contact details private; older private-v1 receipts remain owner-private. Complete ZIP or Connections-only ZIP/CSV is accepted up to 64 MiB, with 8 MiB per selected CSV, 40 MiB selected expansion, 2,000 entries and 100,000 parser records. Only Connections/Profile/Positions/Education/Skills CSV members are inflated; all other original bytes remain recoverable in the privately retained ZIP with an immutable manifest. The browser request stages the original archive and `uploaded` receipt before redirecting to `/profile`; a singleton server worker resumes via Noos pending-job discovery and CAS leases after navigation, disconnect or restart. Profile/Positions/Education/Skills rows are staged before connections so the own profile can appear before the final publication fence. Publication uses bounded chunks and one final fence; no first-N truncation. One process-wide upload body at a time bounds memory, with a 1 GiB runtime cap and 65 MiB multipart ingress cap.

Returning users rediscover current and pending imports in their owner scope; Settings shows receipts and progress/status for each file. A confirmed recovered legacy profile can supply the owner profile fallback, directed contacts and browser-only recovered original-file downloads until the link/source is revoked. My network and the owner MCP tool search all current published owner imports plus live confirmed recovered contacts and sanitized recovered Connections observations, bounded to 1,000 imports/100,000 observations; an exceeded bound fails explicitly. Everyone search uses the separate complete published professional index, initially bounded to 20,000 profiles/100,000 directed edges and ranked from at most 200 lexical candidates. Source IDs and archive provenance remain unchanged. Connection observations are not asserted to be second-degree edges. Every search rechecks complete live publication state after model completion.

The [agent API contract](../../docs/agent-api.md) owns Settings/OAuth permissions, optional connection actions, tool catalogs and degree semantics. Audience: `unlinked-account-tools-v1`. The grant and revocation persist in owner-private operational resources; the domain-separated signing key derives from the approved private graph secret, so unchanged secrets preserve grants across restarts. Replacing that secret revokes every old account grant. Browser session lifetime is documented in [the live pilot delta](../../docs/private-real-guest-pilot-delta.md#access-consent-and-delegation). Copying MCP setup is configuration, not proof that a client connected; a successful authenticated real MCP call is the connection acceptance receipt.

The source tests explicitly distinguish synthetic identity/filesystem persistence from production callback/Noos/model evidence. They cover native upload, disconnected browser controller plus replacement worker, profile-first staging, crash/replay, lease expiry, two-owner isolation and tombstone races, but they are not live Noos/model/browser proof. Live friends' archives remain gated on the exact deployed OIDC callback, actual browser synthetic Connections-only/full-ZIP upload, background continuation, complete counts, real model, MCP/revocation and recovery acceptance. The existing private host is not upgraded by merging source. Preserve the six legacy services and prior private source/graph/assets/env; roll back only the owned runtime and ingress to the pinned release, or maintenance 503.
